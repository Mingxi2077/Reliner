# 后端技术栈与架构答辩

Reliner 以 Windows 本机拓扑实验与排障为主线。轻量性看多文档切换、编辑和运行时的驻留成本。实用性看能否做完一个工单。严谨性看生效输入、模型顺序和结案依据能否说明。排障特色是用同一场景对照两次修订，把每次结果追到当时的设备、端口或规则。已跑通 VLAN、静态 IPv4、双链路主备、IPv4 MTU、链路队列、点到点动态路由和 STP 工单，见[离散事件仿真设计](discrete-event-simulation.md#里程碑)。

## 第一轮 · 关键选型与反例

四位子代理分别审查执行载体、仿真内核、拓扑存储、证据与实栈。下表保留各项反例和三轮之后的主线决定。

| 底层项 | 采用 | 反例、备选与换栈条件 |
| --- | --- | --- |
| 语言与构建 | Rust + Cargo，核心库配薄 CLI，首发目标 Windows x64/MSVC。核心以标准库及 Serde / `serde_json` 为基础。 | Go 适合独立工具，运行时内存限额是软限。C++/CMake 适合直接复用现有原生模型。如果目标工单依赖必接模型，先评估局部 C ABI 或子进程。只有同工单的证据、Windows 交付或资源开销显示候选确实更合适，才换主内核。 |
| 进程与部署 | CLI 和桌面各自调用同一个 Rust 库。CLI 要能在没有开发工具的 Windows 标准用户环境启动。桌面壳通过适配层接入。 | 进程内组件崩溃可能带走当前草稿。异位数 SDK、无法安全停止的组件或操作系统级内存硬限需要独立进程时，隔离相关组件。独立客户端共享后台实验时再考虑常驻服务。 |
| 拓扑与索引 | 文档保存节点、端口、链路的稳定 ID。运行前校验并编译成 `Vec`、稠密索引和邻接表，动态状态由单次运行持有。 | 数组位置会随删改而变。删除后重建分配新 ID，证据引用文档、修订和稳定 ID。若小改动后全量编译成了瓶颈，先比较限额缓存与增量编译。跨文档查询成为常用需求时再评估派生图索引。 |
| 仿真引擎 | 单次实验串行的离散事件引擎。`u64` 纳秒时钟、反序键 `BinaryHeap`，用类型化的帧、ARP、IPv4 与 ICMP 表示首批合法生成的报文。 | 拓扑快照一样，仍可能因在途断链或缓存初态得到不同结果。静态路径分析适合独立的稳态检查。现成 ns-3 的同刻顺序与本项目契约有差异。遇到持续的无线工单，再评其接入和证据适配。坏报文或抓包往返成为需要时，补字节编解码。若堆操作或失效项主导开销，再评估分桶或可删除队列。 |
| 并发与资源 | `std::thread` 固定后台工作池，有界待办队列，运行在完整事件间轮转。受理和派发分开，单次预算在开跑前固定。 | 两级各 64 个下游的无环广播树也能让 4096 个到达事件同时待处理。固定线程数挡不住单事件扇出、编译暂存和暂停态。若编译使短探测排队过久，再在同一总线程额度下拆编译和运行配额。若单事件影响取消响应，再拆可分段的只读准备。 |
| 文件与迁移 | Serde 版本化 JSON，用户保存的文件是持久拓扑和场景的真源。旧版本按原语义迁移。 | 整档读写会随输入尺寸增长。需要高频局部事务或跨文档查询且整档 I/O 已成瓶颈时，再评估 SQLite。若瓶颈来自历史证据，只迁移证据存储。YAML 可做外部导入，二进制编码适合经测量有收益的派生数据。 |
| 结果与传输 | 结构化结案事实和因果证据。CLI 与桌面共用类型和结果编码，默认按运行 ID 拉取摘要、按游标查询明细。 | 逐事件推送遇到慢读者会堆积或阻塞。若拉取延迟确实影响操作，可加合并后的有界通知。跨进程隔离先复用版本化消息，HTTP 或 gRPC 等出现独立或远程调用需求再选。 |
| 第三方与实栈 | 导入适配器映射到规范化文档并保存缺项。真实路由软件通过独立 Linux Containerlab + FRRouting 适配器显式启动。 | 漏导回程 ACL 会把实际可能丢弃的回包判通。维持可查看的文档，对受影响探测给「未判定」。真协议工单反复超出模型覆盖时引入相应实栈，平台可用率、冷启动和并发内存达到交付要求后才重议默认。 |

## 第二轮 · 交叉质询

- **先定受理，再定停点。** 全局空闲内存若逐事件参与扣账，实验 B 的编译就能改掉实验 A 的停止事件。提交时只占输入额度和排队槽，绑定当前生效修订。派发前占用一个驻留份额，用于该次编译暂存、运行态和结案。份额暂缺就等待，任务超过配置可给出的最大额度则在受理时报错。取消排队释放快照和槽位，派发后释放槽位。暂停归还线程并保留运行份额，终止归还份额。历史摘要和明细按各自的保留额度计。应用使用保守额度记账。操作系统级内存硬限属于独立进程的后续验证。
- **调度与仿真计费分开。** 每个模型在事件执行前给出可计算的扫描、扇出和暂存上界。单次硬限决定能否提交。软批次只决定何时轮转，超软批但合硬限的事件独占一轮。失效定时器和作废帧入队后计驻留，出队计工作。若替换队列会改变退账点或停止位置，同一模型版本保留原计费口径，变更口径时升模型版本。
- **定序跨编译一致。** 初始表项按稳定键入队，场景动作按声明序入队。派生事件按父事件的提交序及模型输出序编号，无序扇出按稳定 ID 排。保留有序规则的原优先级和同级声明序。编译重跑、单步、完整运行使用同一规则。内建设备模型随核心编译。模型只读本设备状态并提出状态变更、发帧、定时和判定事实，由内核统一提交。模型须有执行前可核算的事件上界。
- **关闭轨迹也能结案。** 每个声明探测预留基本结果及必要证据空间。收到匹配回包、处理截止或遇到执行中断各自记录。可选轨迹使用独立额度，查询标出未采集、截断或已淘汰的区段。单支丢帧只说明该支，归因须有证据证明阻断影响当前探测的结案。旧报告带当时的设备、端口 ID、名称和规则摘录，查询不用保留整份旧图。
- **导入缺口随文件保留。** 原生文件先读版本，再按该版结构校验和迁移。遇到未知语义字段时报告路径并拒绝加载，声明的展示扩展可以透传。未来版可查看原文。旧版若省略允许列表曾代表全放行，迁移后写明这个语义。第三方未映射项保留作用对象、来源和原始配置项，重新打开时仍参与判定。去程、回程或场景中可能使用的路径受影响且无法排除时，该探测为「未判定」。已证的独立事实仍可展示。

## 第三轮 · 编辑、时钟和证据的取舍

- **实验发起时复制生效输入。** 比较了 `Arc` 写时复制、分块共享、增量日志和逐次快照。首版取逐次快照，只复制影响仿真的字段。同一文档的编辑与取样在共享后台调度中按提交顺序处理，编译交给实验工作池，编译完释放输入副本。暂停保留编译图和运行态。代价是复制耗时随输入增长，紧随发起的编辑要等取样结束。若复跑重复复制和全编已成瓶颈，再评估分块共享或限额编译缓存。打开拓扑只载文档，可回收已保存且空闲的后台文档，未保存草稿继续驻留。
- **保存和运行各有结果。** A 绑定未保存的 R 后，下一笔编辑形成 R+1。「保存并重跑」固定路径和 R+1，写入同目录临时文件后执行文件替换。替换成功后试受理该修订。输入或待办已满就显示「R+1 已保存 · 重跑未受理」，已受理且执行份额暂满则显示排队。写入失败保留草稿并回报系统错误。Windows 替换成功是更新保存状态的边界，断电恢复另行验证。后续编辑留在草稿。
- **固定纳秒和同刻顺序。** `u64` 纳秒无需穿过中间空闲时刻。十进制时间精确转换，负值、非整纳秒或越界输入报错。链路延迟至少 1 纳秒。派生时刻检查加法，溢出停在上一完整事件。生效场景、运行配额和模型版本相同且无外部中断时，比较结案事实、必要证据及逻辑停点。规则见[内核契约](discrete-event-simulation.md#内核契约)。
- **同一结果分开说明现象和原因。** 首个跨网段工单的两类故障在轨迹关闭时也保留下表的最小证据。多次断开和恢复后才处理旧帧时，报告该帧发送代次被首次作废的断链，最后一个在途引用结束后释放旧代次记录。

| 结案现象 | 展示与最小证据 |
| --- | --- |
| 去程在途断链 | 「未收到匹配回包 · 去程在途断链」，保留去程帧和使它作废的断链事件。 |
| 去程已达，回程缺路由 | 「未收到匹配回包 · 请求已达，回程缺路由」，保留目标端收包和回程查表未匹配。 |
| 只观察到旁支丢帧 | 若保留则列在观察明细，附分支、端口和规则。收到匹配回包仍判通，截止且缺因果证据时原因标「未定位」。 |

## 兼容和后续复核

原生文件格式、模型行为和公共接口各自有版本。对外 JSON 的 64 位时刻与标识传十进制字符串。回看读取既有事实，对照重跑把同一场景应用到当前修订，原样复跑需要原生效输入、原模型、原初态、原场景与原配额。缺旧模型或修订时，注明缺项。

当前 Rust 接口版本为 `BACKEND_API_VERSION = 2`。原生格式 1 和 2 仍按各自语义编译、保存与重开，不把旧版无过期缓存强行改成新版有限生命周期。新增格式 3 承载第三方来源与未映射项，报告版本 8、模型版本 11；补齐最后一项缺项也保持该版本。未来格式和损坏文件可通过 `preview_native` / `preview_file` 查看原文；预览不受理运行。

实栈记录生效配置、实际运行的软件或镜像、探测参数与观测时钟。先对齐稳态去回程和下一跳再对照。生效配置、预热或断链语义不一致的项目标「不可比」。FRR 可以佐证对齐后的 Linux 路由与收发。厂商特有配置需要能运行该行为的环境来取证。

后端更换技术时，沿用相同工单和 Windows 负载，比较模型行为、必要证据、文件兼容和已测到的瓶颈。跨网段四组已经实跑通过，见[离散事件仿真设计](discrete-event-simulation.md#跨网段工单)。

## 工作区实现与两轮复核

| 复核问题 | 实现取舍 |
| --- | --- |
| 待办会不会读到后来编辑的草稿 | 先检查待办槽和输入快照额度，再复制仿真实验字段。运行绑定工作区内的生效修订。保存与入队共用一次取样，写盘期间允许继续编辑，画布 `presentation` 与生效修订分别跟踪。 |
| 暂停会不会堵住所有线程 | 待编译按 FIFO，已就绪任务按批轮转。两种任务都能派发时交替取。暂停返还线程，继续或单步复用驻留份额。排队取消立即归还槽与输入额度。 |
| 反复取消或打开轨迹会不会积累状态 | 初始动作先过待处理事件额度。作废代次随最后一个在途帧回收。报告历史和详细轨迹有独立保留上限，淘汰轨迹时仍可分页查询该报告的必要证据。 |

默认工作区为 2 个 worker、8 个待办槽、4 个驻留运行。输入快照总限额 8 MiB，文档总限额 64 MiB，单文档 1 MiB，最多打开 128 份。当前在额度满时明确拒绝新增占用，需要释放文档时由调用方关闭。编译在完整编译返回后响应控制，运行在事件边界响应。额度按任务、数据量和事件估算，进程工作集由本机测量。

## Windows 本机实测

Windows 11 x64，Intel Core i9-14900HX，约 32 GiB 内存，GNU Release。48 / 64 份文档各含 4 份 256 节点、510 端口、255 链路的大图，其余为 32 节点、62 端口、31 链路。每轮切换全部文档，编辑四分之一文档的布局和端口配置。每档两种负载各启动新进程实跑三轮，每轮持续 8 秒。混合负载用 2 个 worker、3 个驻留份额，一份持续暂停，反复提交含 96 个同刻探测的广播拓扑。

| 文档 | 负载 | 配置编辑 P99 最差值 | 峰值工作集 | 暂停 P99 最差值 |
| --- | --- | --- | --- | --- |
| 48 | 纯切换与编辑 | 0.177 ms | 12.17 MiB | — |
| 48 | 混合 | 0.107 ms | 29.51 MiB | 1.70 ms |
| 64 | 纯切换与编辑 | 0.164 ms | 16.86 MiB | — |
| 64 | 混合 | 0.110 ms | 31.75 MiB | 1.65 ms |

上述切换 P99 均低于 0.002 ms，布局修改 P99 低于 0.010 ms。纯编辑编译次数为零；混合负载实测出现编译、运行和暂停同存，待办打满，排空后输入快照和驻留任务均归零。共 8445 次混合负载运行和独跑的结案、证据及逻辑停点一致。表中切换只计工作区返回文档数据的时间，桌面渲染、长期负载与较低配置机器待测。静态 IPv4 里程碑的最终构建另做了 64 份文档、20 秒混合复跑，2337 次运行与独跑一致；配置编辑 P99 为 0.159 ms，暂停 P99 为 3.41 ms。

```powershell
cargo run --locked --release --example workspace-load -- pure 64 8
cargo run --locked --release --example workspace-load -- mixed 64 8
```

双链路里程碑最终构建用同一拓扑集重跑 64 份文档、20 秒混合负载。2445 次运行与独跑一致，配置编辑 P99 为 0.174 ms、暂停 P99 为 3.788 ms，采样到的进程峰值工作集为 38.21 MiB，排空后待办、输入快照和运行份额归零。

链路队列、动态路由和 STP 合入后的 Windows Release 同时打开 64 份文档，轮流执行三类示例。两个工作线程下，192 次运行与同配置独跑一致，6144 次后端文档读取的 P99 为 0.0014 ms，最多 4 个运行驻留，排空后待办、输入快照和运行份额归零。这个数据仅计后端文档读取。

峰值工作集由 Windows 的 `PeakWorkingSet64` 读取，覆盖整个负载进程及测量开销。保存到磁盘的耗时另测。早期 MSVC 发布链接因缺少链接环境停止；首版已补齐静态 CRT 与 Windows 系统链接库，实际交付验证见下文。

### 组合园区的单场规模

以组合工单的 8 台设备、9 条链路、7 发探测为起点。每档扩入等量交换机和路由器。交换机分支通过双 Trunk 参与公共树，路由分支参与邻接和算路，原探测路径、发布的两个网段和故障时刻固定。因此这组数字衡量大拓扑的控制面和工作区后台负载。 [可复跑基准](../examples/campus-load.rs)

早期实现各加 72 台设备时，STP 首轮计费 8297，超过默认单事件上限 8192。按每条物理边最多成功入堆一次的上界计费后，首轮降到 5501。历史按整树留存时，Workspace 在各加 83 台时先触及当时的 2048 条必要证据上限。当前默认额度的实验见下方复测。

### 首版配置、归档与交付

配置检查沿用运行前编译器，按原始文档位置返回首错、错误代码和对象 ID。端口排序、重复 ID 和旧格式不会把错误指向另一个对象。Workspace 检查绑定文档修订，独立查询生效 TTL、载荷和 STP 参数，并区分显式值、模型默认值。配置分页仅构造所请求的设置项，格式 1 的固定参数标为不可配置。Serde 内部标签枚举的字段解码错误可以只定位到设备容器，保留原始错误，不伪造更精确路径。

直接解析失败后才调用字段路径跟踪。520 台固定七发的有效文档，临时分段计时中位数显示，文档反序列化从全程跟踪的 2.61 ms 降到 1.45 ms。最终 GNU Release 与改动前构建交错各三轮、每轮 100 场，固定七发和 3082 发两档的吞吐中位数差异均小于 1%。高密度档单场 P99 为旧版 29.88–34.58 ms、新版 30.95–35.46 ms。

## 第三方导入、桌面调用和实栈入口

本阶段继续后端主线，前端只约定呈现与调用方式。默认实验仍直接运行 Rust 显式离散事件内核；Docker 仅由显式实栈命令启动实验资源。

### 导入和判定

首个适配器读取 Containerlab YAML 的节点、接口和 veth 边，支持简写、展开式端点和 YAML 合并。它导入拓扑结构；设备的主机/路由器/交换机模型、IPv4、MAC、链路时延和场景由独立的显式映射文件补齐。`kind` 和 `image` 保留来源身份；Linux 镜像的启动行为仍是设备缺项，宿主桥与管理网络是全局缺项。导入器不执行源文件命令，不加载外部配置或挂载文件，也不展开变量。未映射的配置保留原文路径、作用对象、原始值与说明。

第二个适配器读取 GNS3 `.gns3` 文件修订 9，保留节点和链路 UUID，以 `a{adapter_number}p{port_number}` 表示端口引用；它不核对设备运行时端口清单。明确标为以太网的边，以及两端都是 VPCS、内置以太网交换机或集线器的无类型边可建模。串行或介质未确认的边列在 `omitted_links`，保留两端引用、原文路径和省略原因；原始配置仍为全局缺项。预览的 `links` 只包含可建模的边。导入仍需显式 `ImportOptions`，不读取启动配置或镜像，不连接 GNS3 服务。项目 `version` 仅作来源信息，旧修订和新修订均不自动迁移。[上游文件模式](https://github.com/GNS3/gns3-server/blob/v2.2.61/gns3server/schemas/topology.py)

缺项按全部物理边划分的设备连通组件归属，包括备用和当前 STP 阻塞的边。探测源或目标所在组件受影响时，通断为「未判定」，原模型结果保存在 `outcome.modeled`；相关事实标 `model_only`。这是保守范围，暂不证明某项策略与某发探测无关。独立第三组件不受局部缺项污染；全局缺项影响全部探测。缺项悬空引用报错。

「执行完成/未完成」与「覆盖是否足够」分开计算。`undetermined` 可同时包含已经收到模型回包和提前停止的探测，不能与 `incomplete` 简单相加。前端先展示「未判定：配置覆盖不足」，展开后再讲模型中发生了什么；不得取 `modeled.reachable` 改成绿色确认连通。缺项只保留一份，探测引用组件，避免探测数乘缺项数的复制。

两个适配器共用 Cisco IOS 单接口配置导入。交换端口可附 `ios_config` 文本，CLI 也可通过可重复的 `--ios-interface 节点 源接口 文件` 绑定。解析器核对接口声明与端口名，读取静态 Access/Trunk 模式、Access VLAN、Native VLAN 和允许列表的完整赋值（编号、区间、`all`、`none`）。允许列表按 1–4094 的模型空间规范化。未声明的必需字段可在端口 `mode` 中显式补齐，补值仅用于模型；冲突返回来源行，已有拓扑导入缺项继续参与判定。单接口段无法证明全局 Native VLAN 标签策略或 VLAN 可用性，因此保留端口范围的上下文缺项。

桌面用 `import.ios.preview` 接收单接口文本。归档沿用格式 3 输入及报告版本 8 的来源结构，`import_source.metadata` 以映射选项路径为键保留实际采纳的字段值和一基行号。`gaps[].source_path` 以 `/lines/N` 定位未映射的输入行；未声明的字段以字段名定位。不支持的列表增删等操作使该字段待补，不将部分列表作为最终值。 [操作示例](../README.md#导入-cisco-ios-交换端口配置)

Windows MSVC 构建实跑了 Containerlab 文件导入：两端 Native VLAN 为 10/20 时在 `r2:eth2` 的 Access 出口拒绝 VLAN 20，改为 10/10 后同一探测收到模型回包。两次归档回读均保留原报告与「未判定」。GNS3 经 JSONL 导入后读回的端口 UUID、接口编号与 Trunk 配置相符。未提供 IOS 配置的两份既有导入示例，生成文件与 0.3.0 ZIP 中的程序逐字节一致。

### 桌面接入

`Backend` 持有持续的 Workspace，`workspace --jsonl` 提供独立进程入口。一次握手返回协议、接口、文件与报告版本、会话 ID 和额度。后续请求携带会话 ID，旧进程的文档或运行 ID 不得命中新进程。64 位 ID、修订和仿真时刻双向使用十进制字符串，分页每次 1 至 128 项。

请求形如 `{"protocol_version":1,"request_id":"1","command":{"type":"hello"}}`，其余请求在外层带握手返回的 `session_id`。`import.preview` 接 YAML 文本，`import.open` 再接显式 `options`，成功后打开未保存文档。`status: error` 的 `error.code` 供程序分支，`message` 只用于展示。运行证据、STP 事件和覆盖引用按 `(session_id, run_id, 引用值)` 保存；新运行可能重复使用事件或组件编号，不能单独追踪裸编号。运行报告已被历史池淘汰时返回 `unknown_run`，不能当作空报告。

GNS3 使用 `import.gns3.preview` 和 `import.gns3.open`，以 `project` 传入 `.gns3` 文本；打开命令另传 `options`。预览可分别展示 `links` 与 `omitted_links`，不能将省略边画成模型已经运行的链路。Containerlab 命令和握手协议版本不变。

编辑、校验、保存、保存并重跑、关闭和运行提交绑定预期文档修订；过期操作明确拒绝。运行来源在受理时固定，文档关闭后仍可回看。保存成功但重跑未受理分别返回，前端保留已保存的状态。

前端首屏取摘要，再按需取探测、证据、链路、路由、轨迹、缺项与比较页。STP 先取发布摘要，再取指定发布的桥和链路行，从压缩历史直接读取所选行。比较按稳定探测 ID 归并，只构造本页；排序索引每份留存报告惰性建立一次，在调度器锁外排序并随运行淘汰。偏移分页仍需扫描前面的 ID，不能把它宣传为任意深度恒定时间。

操作顺序为「打开或导入 → 显式补全 → 校验并查看缺项 → 提交 → 读摘要 → 展开原因 → 编辑后重跑 → 按探测 ID 对比」。前端自行实现画布、交互和视觉设计；本阶段交付可调用后端。

### 实栈范围

计划阶段不需要 Docker。运行阶段仅支持有限规模的稳态 IPv4 主机和静态路由器，记录执行计划、原生修订、实际镜像身份、软件版本、接口与内核路由、探测参数及独立观测时钟。预热、定时断链、STP、动态路由、队列等未对齐语义明确拒绝，带未解决导入缺项的实验也拒绝对照。

对照仅讨论对齐后的 IPv4 收发与内核下一跳选择。有限仿真截止时刻的超时不能直接当作稳态不可达，Linux 查表也不能冒充数据包的实际逐跳路径；仿真纳秒、链路时延和真实墙钟 RTT 不作等值比较。在本机，FRR 10.7.1 Zebra 未能以实验允许的 `NET_ADMIN`、`NET_RAW` 权限启动并装表，镜像不接受 `-S`。当前显式入口使用 Linux 内核静态路由，镜像仅提供工具，不验证 FRR 的装表或厂商行为。

## 0.4.0 之后的候选方向

- 优先考虑「同一台服务器 Ping 通，TCP 443 却连不上」。复用现有 IPv4、探测对照和端口证据，在实验中显式配置服务监听和按协议、目的端口匹配的 ACL。用同一拓扑分别复现握手成功、目标端口关闭后回 RST、途中规则丢弃，以及回包被拦。报告保留观察方向和匹配规则，仅有超时时将原因标为「未定位」。
- 配置兼容按工单扩。可先让 Cisco IOS 导入覆盖上述 ACL 场景；有华为 VRP 配置样本时，再选一类已有模型能表达的交换端口配置，保留来源行和影响结论的缺项。
- 协议深度由具体实验决定。双栈教学可从「同一链路 IPv4 通、IPv6 邻居解析失败」入手；路由课程可从点到点 OSPF 邻接故障入手，用独立 FRR 观测核对邻居和装表变化。
- 新能力沿用文档与运行分离。打开或切换文档只读编辑数据，提交实验后才创建相应运行状态。前端接入后优先看多文档后台重跑时的编辑和切换延迟，再按实测瓶颈决定是否优化快照或编译。上述为候选工单，尚未排期。

## 0.4.1 修复与复测

上表的 16 项缺陷均已修复。文件保存现在按打开或上次保存时的磁盘内容校验，冲突方保留草稿并收到 `save_conflict`。两个新版进程竞争写同一文件时只有一方成功。首次向尚不存在的目标另存使用原子新建。Linux 非 root 进程实测保留了原文件的 `0600` 权限，覆盖 `0444` 文件会报错。

两片独立二层网络分别调度收敛，MAC 学习代次随实际树的变化更新。上轮误判的 A→C 探测恢复为 6673 ns 收到回包；另一域的断链也不会让本域提前恢复转发。模型 14 的新归档拒绝自指父帧，旧模型归档仍保留历史记录。网关修复前后可对比同一发探测。导入、邻居观测及路由对照的修复行为见[随包说明](backend-release.md#041-修复)。

Windows x64/MSVC 的格式检查、Clippy、348 项常规测试均通过；3 项独立 Docker/Linux 测试及 1 项 Python 采集测试通过。实际使用 0.4.1 ZIP 复现上述保存与排障工单。11 个随包实验各运行两次，结果一致，归档后可原样回读。0.4.0 发布程序生成的 11 份示例归档也由新版分别以文本和 JSON 读回。FRR 装表和撤回对照使用已有采集；本轮未另行启动来宾重新装表。

64 份文档的编辑、切换、关闭重开与后台重跑混合负载运行两轮各 15 秒，共核对 3232 份结果。两轮较慢的后端 P99 为切换 0.001535 ms、配置编辑 0.155647 ms、关闭重开 0.139263 ms。排空后等待、驻留和输入占用均为零。这是本机后端短测。固定七发的组合园区在默认单事件额度 8192 下，434 台结案、436 台在首次收敛前触限；520 台的单事件额度为 9823 时七发全部结案。该边界仅适用于示例的拓扑和负载。

## 未来隐患

- **配置导入成功，行为仍可能判错。** 例如用户没有显式配置 Trunk 的 Native VLAN，设备仍有生效默认值。导入器如果只看配置里写出的字段，缺项清单可能为空，模型却会误判无标签帧的去向。纳秒时钟和同刻优先级能固定模型结果，真机断链与到达的先后仍取决于输入和设备行为。[Cisco VLAN Trunking](https://www.cisco.com/c/en/us/td/docs/switches/lan/c9000/lyr2-fwd/vlan/vlan-configuration-guide/configure-vlan-trunks.html)
- **后台任务仍可能拖慢编辑。** 同一文档的编辑排在取样之后，连续小改重跑会反复复制生效输入和全量编译。未保存文档、排队快照、暂停态和证据都能叠加在内存里。少数大图就可能影响切换，混合负载可能比纯开文档更早暴露卡顿。
- **单场规模受事件密度限制。** 广播分支、已失效但仍在队列中的定时器、日后的收敛更新都会挤占额度。事件须完整提交，单个大事件能拖迟暂停和取消。预算可以控制耗用，常用场景若频繁触顶，用户就会反复看到「未完成」。[ns-3 的事件取消与队列占用](https://www2.nsnam.org/docs/manual/html/events.html)
- **事件完整时仍可能难以归因。** 一个分支丢了帧，另一支可能已送达，真正的阻断还可能发生在回程。较少的证据会让复杂工单频繁「未定位」，较重的留存会增加内存和处理开销。
- **扩展和旧行为兼容会持续花成本。** 新增 STP 或动态路由时，端口状态、转发表更新和证据要一起演进。旧文件迁移成功后，原样复跑仍需要旧模型及其计费规则。若常用工单频繁转到 Linux 实栈，Windows 本机的轻量排障覆盖也会受限。
- **桌面和内核同进程会共担故障。** 若分配失败走 Rust 标准库默认的终止路径，仿真和桌面会一起退出，未保存编辑会随进程丢失。[Rust 内存分配错误](https://doc.rust-lang.org/std/alloc/fn.handle_alloc_error.html)

### 处理时机

生效配置、资源、结案和编辑归属已由首个跨网段工单和工作区实验验证。后续协议按实际工单扩展，性能方案由负载测量决定。

| 隐患 | 首版要做 | 扩展条件 |
| --- | --- | --- |
| 设备行为误判 | 生效配置标明显式值与模型默认值。以 Trunk 为例，只有设备行为已确认时才补默认 Native VLAN。影响探测的未知项保留来源和作用对象，结果标「未判定」。 | 某类工单持续被同一缺口挡住时，补该设备行为或使用能运行该配置的实栈。 |
| 编辑和重跑卡顿 | 切换和画布编辑只访问文档数据。运行快照只取仿真字段，编译在后台，按队列和驻留上限受理。当前保留取样期间同一文档编辑顺序等待的代价。 | 取样复制拖慢编辑时考虑分块共享。同修订反复编译时考虑限额缓存。小改后的全量重编占主要耗时才考虑增量编译。 |
| 单场事件量 | 保留扇出、单事件和累计配额，在提交前计费。达到硬限停在完整事件边界，尚未结案的探测为「未完成」。具体配额按目标负载确定。 | 若无效扫描或派生事件占主导，先减少这部分工作。堆操作成为主要开销再换队列。仅需稳态可达性的大规模工单可另加静态分析。 |
| 定位失准 | 最少保留探测结案和能证明阻断的事实。首个跨网段工单覆盖去程断链和回程无路由。证据不足时保留探测结果，原因标「未定位」。 | 复杂工单反复缺证时，优先按探测或端口增加细节采集。 |
| 扩展和旧实验 | 保留独立的文件、模型和接口版本。记录修订和生效输入，有留存的旧报告可直接查询。原样复跑取决于原生效输入及相应模型是否可执行。 | 按工单逐个加入协议。旧模型确有原样复跑需求时再单独交付。 |
| 同进程故障 | 编辑端持有草稿，实验入口只接收生效输入并返回结果与证据。开发主线沿用库和薄 CLI。 | 进入桌面交付时，如果要求内核崩溃后能继续编辑，或接入有独立隔离要求的组件，就用按需独立进程承载相应运行。 |

## 测试场景与虚拟机

- **首版模型测试不需要虚拟机。** Rust 单元和集成测试直接运行内核，使用固定拓扑与场景输入，检查探测结论和因果证据；同刻事件、断链作废、过期定时器、迟到回包及轨迹开关属于本机回归用例。虚拟机不会让模型更真实，只会多引入一层运行环境。
- **Windows 性能验收在原生 Windows 上测。** 分开测多文档切换与编辑，以及编译、运行并存时的排队、响应和内存；不把虚拟机内的数字当作目标机器基线。
- **虚拟机仅用于可选的实栈对照。** Containerlab 需要 Linux 环境和容器运行时；Windows 上可以用 WSL2 提供轻量 Linux 环境。该环境用来运行 FRRouting 等真实软件，观察结果单独标为「实栈观测」，不作为核心模型测试的前置条件，也不与「模型推演」合并判定。
- **当前阶段。** 原生模型在 Windows 本机验证，独立可选的 Linux 实栈已对照直连、静态路由和缺回程；不把 Linux 容器作为普通实验前置条件。
