# 离散事件仿真设计

这里记录按帧和包复现二层、IPv4、双链路主备、MTU、链路拥塞、动态路由和 STP 故障的模型。示例运行方法见[主线文档](../README.md#跨网段排障)和[双链路工单](../README.md#双链路主备排障)。

## 两轮答辩后的取舍

| 方向 | 第一轮反例 | 第二轮交叉答辩后的决策 |
| --- | --- | --- |
| 时间与状态 | 回包、断链、探测截止撞在同刻，结果不能由入队碰巧谁先决定；断开又恢复也不能让在途旧帧复活。 | 固定同刻顺序和截止边界。链路代次、表项代次和探测身份各管一件事；过期定时器不能删新状态，迟到回包不能算到下一次探测。 |
| 实用范围 | 拔掉唯一通路再看到 Ping 超时，不等于能排障；冷启动还会掩盖已有缓存导致的问题。 | 静态 IPv4 路由前移。用同一工单验证「去程在途帧被断链作废」和「去程送达但应答因缺回程路由未返回」；动态路由与主备自动切换后置。 |
| 资源与回放 | 固定线程数挡不住一次大广播，也挡不住同一时刻堆积大量到期项。 | 事件执行前保守计费，事件与事件之间可以让出线程；详细轨迹单独限额。保留必要证据，不为回放逐步保存全量状态。 |

## 内核契约

- **输入显式。** 一次运行固定生效拓扑修订、模型版本、初始状态和有限场景清单。清单给出探测、链路动作、截止点和场景结束时刻；探测截止不得晚于结束时刻，结束时刻上的事件也按序处理。`u64` 纳秒仿真时钟跳到下个事件。时间精确转换，输入越界报错，派生时刻加法溢出则停在上一完整事件，未结案探测标为未完成。单次运行串行，快跑和单步处理同一事件序列。
- **顺序显式。** 事件键用 `(仿真时刻, 阶段, 序号)`。同刻依次处理「链路变更 → 控制收敛 → 到期定时器（含探测截止）→ 等待帧开始发送 → 帧到达 → 启动邻居预热或探测」。同链路同刻重复变更在提交时拒绝。同组同刻的两条物理变更合为一个事件，同阶段按稳定序号处理。版本 2 的初始表为空，按链路动作、预热、探测三个清单各自的声明顺序登记预定动作。派生事件按父事件提交序和模型输出序编号，无序扇出按稳定 ID 排列。内核派生的排队事件必须在未来：固定链路延迟为正，MAC 学习、选出口、查路由等本地动作在当前事件内完成，不借内联启动另一个阶段的动作。
- **断链只改变声明的行为。** 首个时序模型的断链是媒体中断，不模拟管理关闭、设备缓存清除或路由撤销。发送记录链路代次；断开递增代次，到达时只有链路可用且代次一致才交付。因此不必在断开时扫描队列，旧帧也不会因恢复而复活。证据记录原计划到达和发送时的代次，并指向使该代次首次作废的断链。该代次的在途引用处理完即可释放旧代次信息。
- **生命周期显式。** 版本 1 从空表开始，使用旧版的单探测表项语义。版本 2 从空表和所有链路连通开始，用 `warmup` 声明预热 ARP，`arp_lifetime_ns` 和 `mac_lifetime_ns` 必须显式提供。多次探测共享同一运行的 ARP 和 MAC 表。断链不主动清表，表项继续按模型声明的期限老化。受保护端口的 MAC 表项还须匹配学习时的转发代次。`t == expires_at` 即失效，创建、刷新和删除后重建表项都分配新的代次，定时器只处理它创建时绑定的代次。寄往本接口、通过校验的迟到 ARP 应答仍可学习或刷新；只继续尚未截止且等待该地址的探测，不复活已结案的等待。一开始不做宿主系统级的邻居探活和重试机制。
- **探测和网络事实分开。** 只有匹配地址方向和 ICMP 标识、序号的回包，且 `到达时间 < 探测截止`，才算成功；同一场景内，相同源目地址对不复用标识和序号组合。晚到仍可正常进入网络处理，但不能改已结案的结果。处理完本次探测的截止事件才可报「未收到匹配回包」；取消或超限只把尚未结案的探测标为未完成，保留已结案结果与已提交事实。未建模的行为若可能改变结果，就拒绝作出通过或失败的判定。
- **证据跟着判定走。** 设备处理一次收帧或查表时，同时产出状态变更、后续事件和必要的判定事实。证据按探测、帧及其复制分支关联方向、端口、实际匹配的规则。旁支丢帧不能直接归因；只报告证据能串起来的实际阻断，不声称指出了所有后续问题。证据不足时仍可报告探测事实，但不猜阻断位置。

## 里程碑

1. **二层纵向打通。** 在 CLI 跑通无环拓扑、Access、只收发带标签帧的 Trunk、MAC 学习、ARP 和 IPv4 Ping。加载同一个实验，比较 VLAN 正常与漏放；被入口拒绝的帧不得学习或转发。能区分 ARP 未完成与 Echo 请求已发出但未收到匹配回包。
2. **首个实用里程碑。** 已实现直连和静态 IPv4 转发（最长前缀、下一跳解析、TTL；回程独立查表），并加入有限的定时断开、恢复与多次探测。不做任意拓扑热改。两个增量用下表的同一个跨网段场景合验，不能各演示一次就算排障闭环完成。
3. **双链路主备工单。** 已实现同一对交换机的显式主备切换、切回和备用口 VLAN 排障。STP 和动态路由各有独立工单。固定传播延迟不能拿来预测拥塞；小包 Ping 成功不能排除 MTU 或应用故障。Containerlab + FRRouting 独立标为「实栈观测」，不混入模型证据。

4. **IPv4 MTU 工单。** 已实现固定 DF 的 Echo 探测，定位实际丢弃出口，支持改配置后用原探测重跑和对比。

### Native VLAN 工单

- 格式 2、3 的 Trunk 可声明 `mode.native_vlan`，范围 1–4094。入方向有标签取帧标签，无标签取接收端的 Native VLAN；两者均检查允许列表。出方向先检查允许列表，匹配本端 Native VLAN 时不加标签。同一物理链路两端允许配置不一致，由实际转发产生结果，不在校验时判错。
- 同时使用有限发送队列时，链路按实际有无标签的帧长计费。无标签被映射至接收端 VLAN 后再学习 MAC。报告保留实际丢帧点，例如入口允许列表或目标侧 Access 口的 VLAN 不匹配；不把全部超时归因于 Native VLAN。
- 未声明时保留全带标签模型，原有报告不变；显式声明时使用模型版本 12，报告结构和归档格式不变。生效配置页列出端口 ID、JSON 路径和显式值。适配器可使用该显式映射字段，但不能据此推断厂商默认行为或移除导入覆盖缺项。 [故障示例](../examples/native-vlan-lab.json)

### 跨网段工单

1. **先实现静态 IPv4。** 用 `PC-A → R1 → R2 → PC-B` 验证主机按显式网关发出跨网段报文、路由器逐跳查表并解析直接可达的下一跳。保留现有二层文件作为回归。先跑通往返，再只删 `R2` 上去往 `PC-A` 网段的静态路由。报告要把目标主机收到请求和 `R2` 对应答查表未命中这两条事实关联起来。
2. **再把定时断开和恢复加到同一个场景。** 每次探测有独立身份，同一场景共享网络状态。报告按探测分别关联在途帧、断链事件和回程查表事实。四组对照全部得到预期结果后，完成这个里程碑。

跨网段对照场景：固定探测时间与初态，用不依赖该回程路由的流量预热，并核对第一发前有关表项一致。第一发请求已进入中继链路，在它原定到达的时刻触发断链；第二发在预定恢复时刻之后发起。只改变「是否断链」和「是否配置回程路由」，预期如下：

| 是否断链 | 回程路由 | 第一发 | 第二发 |
| --- | --- | --- | --- |
| 否 | 齐全 | 通 | 通 |
| 是 | 齐全 | 请求在途作废 | 通 |
| 否 | 缺失 | 已到目标，回程查表未匹配 | 已到目标，回程查表未匹配 |
| 是 | 缺失 | 请求在途作废 | 已到目标，回程查表未匹配 |

四组均已在 Windows x64 GNU 发布程序验证。每组分别关闭和开启详细轨迹，各实跑三次。同一输入重复输出一致。三次链路邻居预热建立六条 ARP 项，预热只使用直连接口。第一发计划于 1200 ns 到达 R2，该时刻的断链优先作废在途帧。恢复后第二发于 2300 ns 到达 PC-B；缺回程路由时，应答于 2400 ns 在 R2 查表未命中。

### 双链路主备工单

- 版本 2 的 `links[].standby_for` 引用同一对交换机上的主链路。成员只属于一组，配对后按同一条逻辑边校验二层无环。两个物理成员共享必经分支索引，各自保留传播延迟、端口模式和 VLAN 允许列表。
- 双方物理初态为 Up。只在主链路物理 Down 时选择仍连通的备用链路，主链路恢复立即切回。两个成员同刻变化时一次提交，按两个物理动作预扣工作量和必要证据。两条都 Down 时，丢帧证据带两个物理断开事件。模型范围为预先声明的点到点双链路，STP、LACP、收敛等待和实栈行为另行处理。
- 先选现役成员，再在实际端口执行 VLAN 判定。被选中的成员失去转发时推进该成员代次，在途旧帧到达时引用首次作废事件。已学习的 MAC 命中须通过同一代次检查，失效后按未知单播处理并计泛洪成本。切换只更新两端的泛洪估算，保留全部端口的固定检查费，VLAN 列表成本随转发成员变化。失效记录继续占用配额，直到老化或被新学习覆盖。ARP 表继续使用原生命周期。
- 启用主备的场景使用格式 2 输入和版本 3 的报告与模型。`settings.protected_links` 保留初始主备配对，初始生效的是主链路。`link_events` 每行对应一个事件 ID，同刻第二个物理变化在 `simultaneous`，角色前后值在 `protection`。用运行 ID、事件 ID 和物理链路 ID 定位物理变化。分页偏移按执行顺序计算。VLAN 丢帧的 `protected_link` 带实际链路和选中它的事件 ID，初始选择为 `null`。退出转发的在途丢失单列实际作废时刻和原定到达时刻。两条都断时标记双链路，证据所带端口是丢帧侧主口，用于定位该交换机。`Workspace::run_link_event_page` 在结案后可分页读取切换，无需详细轨迹。

两轮答辩的反例已并入[回归](../tests/failover.rs)和[工作区测试](../tests/workspace.rs)。第一轮确认待机口不能抢占归因、切换后失效的 MAC 须走真实备用口、在途帧会受切回影响。第二轮复现了非现役端口的 VLAN 列表触发错误限额，修复后扩大该列表仍可达。另核对同刻组内成员、作废时刻和修订间的证据引用。Windows GNU Release 中，故障和修复版各开关详细轨迹重复三次。对同一修订，轨迹开关和截断均不改变结案与证据。旧 VLAN 与静态 IPv4 示例的 JSON 保持逐字节一致。

### IPv4 标准 ACL 工单

[示例](../examples/acl-lab.json) 中 PC-A 探测 PC-B。请求在 600 ns 到达 PC-B，应答使用源地址 `203.0.113.20`。700 ns 时 R1 选出回程端口 `r1-a`，其出口第 1 条规则拒绝 `203.0.113.0/24`，遮住了第 2 条针对这台主机的放行规则。运行 `reliner run examples/acl-lab.json --json`，沿探测的 `request_evidence_id` 查看请求送达事实，再沿 `outcome.cause` 查看应答的 ACL 判定。

将 `r1-a.ipv4_acl.egress` 中的 `permit 203.0.113.20/32` 移到 `deny 203.0.113.0/24` 前面，用原探测重跑。放行证据记录新的第 1 条规则，PC-A 在 800 ns 收到应答，网段内其余源地址仍受原拒绝规则约束。

- 格式 2、3 的路由器端口可加 `ipv4_acl`。至少声明 `ingress`、`egress` 中的一个方向。每个方向是有序数组，最多 64 条，每条含 `action`（`permit` 或 `deny`）、`network`（规范 IPv4 网络地址）和 `prefix_length`（0–32）。按当前包的源地址从头匹配，第一条命中即决定。已声明的方向在没有命中时隐式拒绝，空数组拒绝全部。省略的方向直接通过。
- 入口在二层接收检查之后、TTL 处理之前执行。出口在路由选定实际接口之后、下一跳校验、MTU 和 ARP 之前执行一次。ARP 独立处理，邻居解析完成后续发已放行的包。每条判定证据记录探测、到达帧、事件、接口、方向、包的源和目的地址及动作。`matched_rule` 给出从 1 开始的规则号和源前缀，隐式拒绝时为 `null`。详细轨迹关闭或截断时仍保留判定证据。
- 路由器 IPv4 到达事件预扣本入口和本机最大出口规则表的工作量，各已配置方向计 1 加规则数。放行和拒绝均计入必要证据配额，超限停在前一完整事件。配置 ACL 的运行使用报告版本 9、模型版本 13，沿用归档格式 1。省略 ACL 的实验沿用原有版本选择。 [回归测试](../tests/ipv4_acl.rs)

### IPv4 MTU 工单

- 格式 2 的主机 `port` 和路由器 `ports[]` 可声明 `ipv4_mtu_bytes`，范围 68 至 65535，省略时跳过这个出口的尺寸检查。`scenario.probes[].payload_bytes` 是 ICMP Echo 载荷，范围 0 至 65507，默认 56。两个字段填写时须为整数。IPv4 总长按无选项的 20 字节首部加 ICMP Echo 的 8 字节首部和载荷计算，请求与回应保持同样的载荷长度。
- 首轮答辩确定检查顺序。先处理到达与 TTL，再查路由、确认下一跳，随后按实际 IPv4 出口检查 MTU。尺寸合格后才进入 ARP 及链路发送。每个 IP 包只存一个长度值，超过 MTU 时在当前事件提交丢弃。模型固定 DF 并按探测截止时刻结案。源端出口拒发时仅等探测截止，`waiting_for` 为 `probe_deadline`。IPv4 分片、路径 MTU 发现和线上 ICMP 差错送达属于后续模型范围。 [RFC 791](https://www.rfc-editor.org/rfc/rfc791.html) · [RFC 792](https://www.rfc-editor.org/rfc/rfc792.html) · [RFC 1191](https://www.rfc-editor.org/rfc/rfc1191.html)
- 声明任一新字段的场景输出报告和模型版本 4，其中 `settings.ipv4_dont_fragment` 为 `true`，探测记录带生效载荷。丢弃证据 `ipv4_mtu_exceeded` 带当时的 `ipv4_total_bytes` 和 `mtu_bytes`，端口为实际出口，`fact.packet_kind` 表示本次尝试出站的方向。第二轮答辩将出站尝试的方向与触发它的入站帧分开，用 `fact.event_id` 关联轨迹。目的主机收到请求的证据由 `request_evidence_id` 单独引用。启用详细轨迹后，`route.ipv4_mtu` 同时记下出站方向、尺寸和通过与否。丢弃证据独立于轨迹配额。
- 工作区按探测 ID 对齐前后两次运行，生效载荷参与参数判等。两个修订都使用版本 4 并只改出口 MTU 时，仍是同一探测。原有格式 1 和格式 2 示例继续输出报告 1、2、3。 [实验和修复步骤](../README.md#ipv4-mtu-排障) · [MTU 回归](../tests/mtu.rs) · [工作区](../tests/workspace.rs)

### 链路速率和有限发送队列工单

- 格式 2 的物理链路可声明 `transmission.rate_bps`（正十进制整数字符串）和 `transmission.queue_frames`（0 至 65535 个等待帧）。全双工，两方向各有 FIFO。正在发送和传播中的帧均不占等待位置，等待帧在开始发送的时刻释放一个位置。出口忙且等待位置用完时尾丢。省略 `transmission` 的链路沿用传播延迟模型。
- 发送时长为 `ceil(MAC 字节数 × 8 × 10⁹ / rate_bps)` ns，收端在发送结束后加传播延迟收到整帧。MAC 字节数包括 14 字节首部、4 字节 FCS、实际出口标签和负载，含填充至少 64 字节。ARP 负载为 28，Echo 使用 IPv4 总长度。此计时口径从目的 MAC 到 FCS，物理层前导码、SFD 和帧间隔留给线速模型。
- 两轮答辩定下准入和驻留规则。同一事件的后续发送须看见前序预约，一方向只留发送尾时刻和等待数。排队帧只占一个堆记录，开送时替换为到达，并沿用准入时预留的到达序号。计划越过场景尾部的帧仍参与之前的排队。断链或退出主备转发释放两方向的队列，代次作废同时覆盖等待、发送和传播中的旧帧。旧动作仍占待处理事件配额，必要丢失证据在原定到达时判定。
- 声明速率的场景输出模型和报告版本 5。`settings.transmissions` 列出链路配置；`transmit_queue_full` 事实带触发 `event_id`、`link_id`、容量、速率和 MAC 帧长，证据端口为实际出口。详细轨迹开启时可看到有效的 `transmit_start` 和作废的 `transmit_cancelled`。窗口不足或关闭轨迹时仍可读取必要丢弃证据。

Windows GNU Release 已用[拥塞示例](../examples/congestion-lab.json)验证低负载、突发队满和修改容量后修复。两个修订分别连跑三次，报告一致。验证还包括双方向同时发送、ARP 一次放行多帧、等候释放及到达同刻、带标签帧取整、断链或切回后的代次和工作区保存重跑。版本 1–4 的四份既有示例文本和 JSON 与改动前一致。 [回归](../tests/congestion.rs) · [工作区](../tests/workspace.rs)

### 动态路由工单

- 格式 2 路由器的 `link_state.peers` 按本机口声明正代价，邻接要求物理直连、两端启用、网段和掩码一致。单端未启用和子网不一致各有诊断。`link_state.advertise` 按连接中的本机接口发布直连网段，物理断开后在下一轮撤回。首版是点到点 IPv4 的链路状态模型，OSPF 报文、区域和真实收敛时长由实栈实验覆盖。
- `scenario.routing_convergence_ns` 是正时长。初次到点安装，后续由首个相关物理变化开启固定窗口。窗口内及到期同刻的物理变化合入同轮。每路由器在同一时刻的控制阶段按路由器 ID 依次计算与提交，新表按最小累加代价、首跳路由器 ID、出接口 ID、起源路由器 ID 取一条。逐包先比最长前缀，同长度按直连、静态、动态取胜。启用动态模型的路由器只匹配物理可用的直连项。等待 ARP 的包保留已经选定的出口和邻居。
- 两轮答辩验证了三层三角形、单端配置、等价路径、断链窗口、前缀优先级与同刻更新。第二轮修正了断开的直连遮住已学习路径、等量换表占用和场景尾部的收敛边界。SPF 临时工作按图和前缀上界预扣，驻留额度按换表后的净表项数。版本 6 的 `routing_events` 记录路由器、提交事件及触发链接；`dynamic_route_miss` 关联查表时的收敛与请求送达证据。详细轨迹增加被选出口、发布者和累计代价。

模型版本 9 引入按物理路由邻接图预留 SPF 堆。令 `E` 为物理邻接边数，`deg(v)` 按物理重边计端点度数。每轮逐路由器最多入堆、出堆各 `E+1` 次，峰值按 `min(max(1,E), 2+Σmax(0,deg(v)−2))` 预扣。正代价使每个点只结算一次，已结算点构成连通集合。每个已结算非源点消耗一条内部边的入堆项，其余关联边才可能占用堆，包括尚未清出的过期项。此界涵盖断链、等价首跳和双向不同代价。节点、双向弧、前缀选择与排序另计，路由历史扩容沿用确定的逻辑容量计搬移。逐路由器提交与同刻顺序照旧，工作量停点按模型版本区分。

当前动态路由场景使用模型版本 10，含 STP 的组合工单也使用版本 10。报告格式分别沿用版本 6 和 7。每个有限 Echo 探测在编译时记录请求、回包目的地址是否被配置中的发布前缀覆盖。发布前缀转成闭区间，按起点排序并保留终点的前缀最大值；两次查询按对数时间完成，重叠、嵌套、`/0`、`/32` 均按相同规则处理。运行时只在已装表仍无匹配时读取覆盖标记，区分未配置发布和到已发布前缀无路可达；链路断开不会删除配置意图。尚无首张表仍报等待首次收敛。IPv4 事件按本机静态表、已装动态表和常数次标记读取预扣，停点不再随无关路由器数增长。原生文件不存派生标记。后续新增目的地址可变化的报文时需同步扩展查询方式。[证据边界实测](backend-technology-stack.md#逐包诊断与必要证据边界)

Windows GNU Release 按[示例步骤](../README.md#动态路由排障)保存并重跑两个修订。主路径、绕行和恢复的回包分别在 1600、3800、5600 ns。每个修订三次报告一致，工作区可用原始运行 ID 同时追回程阻断和当时的路由表提交。 [回归](../tests/routing.rs) · [工作区](../tests/workspace.rs)

### STP 工单

- 格式 2 的 `scenario.stp_convergence_ns` 启用全网单实例，覆盖交换机间点到点链路。根桥按 `stp_priority` 再按设备 ID 选，默认优先级 32768，配置值为 4096 的倍数。根端口比较累计代价、发送桥 ID、发送端口 ID 和本地端口 ID，成本从接收端配置的 `stp_cost`（默认 1）累加。每根链路比较两端已知的到根开销、桥 ID 和端口 ID 来选指定端口，另一侧按根端口、备用或物理禁用分类。显式链路主备和 STP 各用于独立实验。
- 初次选树前，交换机间链路保持阻塞。收到物理状态变化后保留上次树的选择，物理 Down 即时生效，恢复物理连通的旧树边等到窗口结束才获准转发。窗口到期一次提交活动树、必经路径索引和洪泛计费。收敛和帧同刻时先选树。退出树的旧链路代次作废，帧在原定到达点留下 `in_flight_stp_loss`。旧树发出的晚到帧仍可沿保留链路完成交付，其源地址学习不会写入新树。传播中的必经分支标记随广播副本保留，避免切换后错归因给旧旁支。
- 模型计算公共树角色，VLAN 过滤在数据面按原规则执行。BPDU 交换、每 VLAN 树、协议定时器握手和真实设备收敛由独立实栈观测覆盖。报告版本 7 的 `stp_events` 按运行回查各轮根桥、累计代价和每端口角色。实际 VLAN、队满或等待恢复的证据带 `stp_event_id`，供界面显示该链路被选中的依据。`stp_awaiting_convergence` 同时关联物理恢复事件。必要角色记录按桥、链路与端口计费，额度不足时整轮树保持原状。

Windows GNU Release 已跑[三角拓扑](../examples/stp-lab.json)的初始阻断、物理断链、绕行、恢复重现和改代价后的四次成功。两个修订分别连跑三次，报告一致。两轮答辩的反例覆盖同刻短断恢复、平行链路、活动 Trunk 的入口 VLAN 工作量、退出链路的在途作废、保留链路的旧帧学习和工作区保存重跑对比。 [回归](../tests/stp.rs) · [工作区](../tests/workspace.rs)

STP 首轮保留完整桥与链路状态，此后按稳定槽位只追加变化行。每次独立发布仍保留事件头，即便所有角色与开销都相同。额度按一条事件头、每条变化桥一项、每条变化链路及两端角色三项预扣。先通过检查，再一起提交树、恢复门控和历史。变更行的容量按逻辑倍增，可能搬移的记录预先计入单事件工作量，停点与实际分配器无关。

STP 模型版本 8 按不同邻桥对约束选树堆工作，每个物理连通分量另外计入根项。对同一邻桥，按接收开销、发送端口、本地接收端口选第一条在线候选。全部物理边仍参与角色判定。必经分支索引在编译时将可能随 STP 变化的交换区域及其接入边编成紧凑邻接，收敛时只重建该部分。直连 IP 链路和未参与 STP 的接入段直接查询编译期索引。每条受管边的两个端口更新及历史追加搬移仍纳入预扣。报告格式保留版本 7，额度触发的停点按模型版本区分。[Windows 默认停点复测](backend-technology-stack.md#stp-单事件与默认停点复测)

CLI JSON 逐轮展开原有完整数组，Workspace 分页只展开所请求的轮次。通过 `run_stp_event(run_id, event_id)` 可直接回查丢帧时的树。Rust 的 `ScenarioReport.stp_events` 使用 `StpHistory`，用 `get(index)` 或 `iter()` 取得完整事件。Windows 回归验证零变化轮仍能被 VLAN 证据引用、乱序分页能恢复旧树，额度差一项时停在提交前。

### 组合园区工单

- [组合园区示例](../examples/campus-lab.json)在同一场景用 STP 切换接入路径、独立重算三层转发表，并在绕行链路上限速。每次只调整 VLAN 允许列表、仿真收敛时长或等待容量中的一项。四个修订的 Windows CLI JSON 各复跑三次一致。Workspace 从磁盘重跑、对比同探测参数，并用原运行 ID 回查修订 1 的队满证据。
- 回包队满用请求送达事实和实际出站方向定位。两发的 MAC 帧分别为 102、64 字节，在 1 Gbit/s 发送方向上的占用分别为 816、512 ns。第二发提前 1 ns 会在 R1 请求出口丢弃，原始场景则在 R2 回包出口丢弃。把 STP 发布提前到首发回包经过旧树的原定到达时刻，旧回包按树切换作废。诊断未获得阻断证据时保留超时事实，原因显示「未定位」。
- 带动态下一跳的阻断证据补充可选 `routing_event_id`，指向该次选路实际使用的安装事件。这个 ID 随等待 ARP 的包、邻居解析和实际出站帧保留，开启、关闭或截断详细轨迹时一致。用 31000 ns 同刻装表和 ARP 应答复现，等候包及邻居应答的阻断仍能定位到 11500 ns 选用的旧表。界面先呈现送达、方向、故障端口和规则，再通过 `run_routing_event_page` 展开安装时刻。链路状态和 STP 依据分别沿已有的物理事件和树事件 ID 查询。
- 把必要证据额度降到 25，场景在 4500 ns 完整提交断链，拒绝 5000 ns 的新树。已经超时的 VLAN 探测保留原判，后续探测为未完成。Workspace 与独立执行核对停点、证据和已发布的树一致。 [回归](../tests/workspace.rs)

### 高密度探测的结案摘要

必要证据预检只计入本事件将提交的记录。非 legacy 场景按原顺序保留每发探测第一个有效阻断原因。ARP 在同事件解除等待时，先按提交规则处理旧原因，再决定哪些新的阻断证据入账。两次真实发送分别保有各自的记录。静态路由回送反例中，401 ns 的 ARP 应答丢失仍为主因，403 ns 被归因规则跳过的候选不再提前触顶。额度不足时整次事件仍原子停止。 [路由与 ARP 回归](../tests/ipv4.rs) · [同事件放行回归](../tests/congestion.rs)

CLI 格式 2 实验未完成时，首屏给出已结案、连通、超时、发包前拒绝和未完成数，以及停止原因、额度和最后完整事件。未完成探测在明细中保留独立标记。即使全部探测已结案，后续事件发生时间溢出，整场仍按停止原因报告未完成。

Workspace 在产生报告后才发布 `probe_counts`。资源限额停止时同时发布 `stop_limit`，数字取该次生效设置。排队即取消、编译失败和执行中没有最终计数。 `last_event_id` 为空表示还未提交事件，有 ID 时 `last_event_ns` 可以是 0。轨迹淘汰后终态摘要可读，运行历史按原有保留额度清理。CLI 完整报告 JSON 的结构沿用原格式。

## 资源与验收边界

- 打开拓扑不创建仿真运行态。后台固定工作池。受理时固定生效输入并限制排队和输入驻留量，派发前预留独立的运行份额，编译后释放输入副本。全局空闲资源决定能否受理或派发，运行的逻辑停点由该次固定配额决定。每个事件在执行前按上界计入扫描、扇出、待处理事件和暂存；另限累计工作与驻留占用。失效定时器和作废帧尚在队列时计占用，出队也计工作。总额度不足就停在上一个完整事件，不推进仿真时间；单批软额度用完就在事件间让位，即使下一事件还是同一时刻。超软批且符合硬限的完整事件可独占一轮。不先做可中断的半事件事务。
- 单步和暂停只在完整事件边界发生。详细轨迹限额单列，开关和截断不得改变网络判定；关键证据也有固定保留范围。取消或超限时可读取已提交结果与停止原因。回放只读证据，复跑则从相同初态执行完整场景；不把冷跑第二发当成复现同一场景里的第二发。不把队列长度当完成百分比。
- 实现后的最低验收：截止点前一刻的匹配回包成功，恰到截止是晚到；帧在 `t=8` 发出、`t=9` 断链、`t=10` 恢复、`t=11` 原定到达，不得交付；旧到期事件不得删除已刷新条目；切换单步或详细轨迹不得改判；在截止前取消或触顶不得补写超时。用上面的跨网段对照查具体原因，不只对最终通断。已在回归中验证回包截止、到达时刻溢出、恢复前后旧帧作废、ARP 刷新代次、迟到 ARP 应答的处理顺序、单步一致性以及配额耗尽后保留结案。文档和混合负载实测见[后端实测](backend-technology-stack.md#windows-本机实测)。

变量由版本 2 输入和运行配额公开。模型使用 TTL 64 作为未声明的请求 TTL 和新建应答的初值。静态路由按最长前缀取胜，同前缀直连优先；静态下一跳须从指定端口直接解析。当前未统计真实网络工单覆盖率。构建、拓扑文件、调度与实栈的取舍见[后端技术栈与架构答辩](backend-technology-stack.md)。
